# 词律探微 · 清代词律声情研究助手

一个用来研究**清代词作声律（平仄格律）**的网页工具。

你问它"这两首词哪一首仄声更密"，它**不会让 AI 猜**——它真的把每个字的平仄查出来、数出来、算出差值，再把计算过程和依据一起摆给你看。

> **AI 只负责把数字讲成人话，不负责产生数字。**

在线版本：**v0.3.2** · 语料 **65,124 首** · 50 个接口 · 18 个页面 · 258 个测试

---

## 一、这个项目在干什么

### 问题

词有格律。同一个词牌，不同作者填出来的平仄分布可以差很远。研究者想问：

- 同调的两首词，全篇平仄比例差多少？
- 上下片之间，仄声比例变化了多少？
- 三首词按后段仄声比例排序，谁最高？差几个百分点？

这类问题**必须精确到字**。让大模型去"读一遍然后估计"，答案不可复现，也没法核对。

### 做法

```
一首词
  ↓  逐字查平仄（本地字典 + 多音字修正表）
  ↓  按词谱切分段落、识别体式
  ↓  统计：平/仄字数、比例、分段变幅、长句密度、排序
  ↓  把每一步的中间结果作为「证据」一起返回
  ↓  最后才让模型把这些数字写成一句人话（可选，且标注"未验证"）
```

**关键取舍：**

| 谁 | 负责什么 |
|---|---|
| 引擎（确定性代码） | 所有数字、平仄、比例、排序、证据编号 |
| 模型（LLM） | 只把已算好的事实组织成叙述，不新增事实 |
| 人 | 最终判断与签字 |

如果模型不可用，系统会如实标注"模型不可用，以下为模板回落"，**不会伪造一段像模像样的分析**。

## 二、能做什么

### 五类可自动求解的问题

| 编号 | 类型 | 典型问法 |
|---|---|---|
| **C1** | 同调全篇声律比例差 | 这两首《临江仙》，全篇仄声比例差多少？ |
| **C2** | 跨篇分段变幅比较 | 甲、乙两首词，后段减前段的仄声比例变化值各是多少？ |
| **C3** | 跨篇长句仄声密度比较 | 哪一首的长句仄声更密？ |
| **C4** | 跨篇后段排序与比例差距 | 三首按后段仄声比例排序，第一名比第二名高多少？ |
| **C5** | 跨篇景情节奏互证 | 景语、情语的分布与节奏如何对应？ |

题面需要包含**作品锚点**（如 `甲：清·费墨娟《临江仙·寄怀阿嫂》`）和**关键词**（如"后段减前段"）。识别不了的题面会明确拒绝，不会硬猜。

### 其他功能

| 页面 | 作用 |
|---|---|
| 题面求解 | 直接贴题，返回五类答案 + 证据链 |
| 解析新词 | 贴一首你没见过的词，逐字标平仄、匹配词牌与体式 |
| 检索 | 按词句、作者、词牌检索 6.5 万首语料 |
| 词库 / 词人 / 词牌 | 浏览与统计 |
| 对比 | 两首词并排比声律分布 |
| 风格画像 | 词人或作品集的声律风格特征 |
| 情感候选 | 只给候选方向，明确不做情感判定 |
| 图谱 | 词人、作品、词调之间的关系图 |
| 问词 | 针对单篇作品自由提问（走事实卡 + 受约束生成） |
| 差异校订 | 版本差异比对，导出修正表（不写回） |
| 论证辅助 | 勾选证据，让模型起草论证段落 |
| 评测中心 | 上传 CSV / Excel 批量评测，导出五列结果 |
| 不变量 | 13 条系统不变量与自检状态 |

## 五、数据

| 层 | 数量 | 说明 |
|---|---|---|
| **Tier 1 官方** | **423 首** | 唯一基准口径。清 200 / 宋 203 / 元 20，243 位词人，100 个词牌 |
| 公开整理本（清） | 26,742 首 | 非官方口径，界面标注来源 |

| 公开整理本（历代） | 10,678 首 | 同上 |

**五层语料严格分口径，永不混算。** 同一个词牌在不同层可能对应不同体式，检索与统计都按层分开。

第三方语料**仅在构建期使用，不随交付物分发**；官方全库（58,851 首）从未发布，本项目接入的是题库参考资料所列的公开整理本。

## 六、技术栈

| 层 | 选型 |
|---|---|
| 后端 | Python 3.11 · Flask · waitress（纯 HTTP，TLS 交给反代） |
| 前端 | React 18 · TypeScript · Vite |
| 数据 | SQLite（含 trigram 兼容层，系统 SQLite 太老时自动切 `pysqlite3`） |
| 部署 | systemd · 自建「GitHub Release 拉取式」发布链路 |
| 测试 | unittest，258 个用例 |

部署链路：

```
本机 scripts/release.sh  →  GitHub Release（资产 = 交付包 tar.gz）
                                    ↓ 服务器部署代理轮询（300 秒）
                          分片下载 → 解压 → 切软链 → 重启 → 健康检查
                                    ↓ 失败自动回滚
```

服务器**主动拉**而不是 CI 推，因为服务器出网约 35 KB/s 且单次下载超过约 3.9 MB 会截断，`deploy_agent.sh` 用 2 MB 分片 + Range 请求 + 大小校验绕开。

```bash
# 1. 后端依赖
pip install -r app/backend/requirements.txt

# 2. 前端构建（产物给后端直接托管）
cd app/frontend && npm install && npm run build && cd ../..

# 3. 起服务
```

```bash

python app/scripts/check_contract.py           # 前后端端点一致性
```

## 八、六条不能碰的红线

对应 `docs/adr/0001–0008`：

1. 模型不参与声律事实判定
2. 各层语料不混算（官方 / 同源分层独立统计）
3. 未知一律拦截，不猜
4. 运行时零外网依赖
5. 不做情感识别，只给候选方向
6. 校订闭环止于导出，不写回

## 九、已知边界

如实列，不粉饰（完整版见 [`app/reports/最终盘点V2.md`](./app/reports/最终盘点V2.md)）：

| 项 | 现状 | 能不能补 |
|---|---|---|

| 官方史证数据 | 官方接口 `total=0` | 不能，等官方发布 |
| 体式消歧人工抽样一致率 | 未做（无人工核验资源） | 不用模型复核冒充人工 |

| 韵位匹配 | 词谱只给韵数与平仄，不含韵部名 | 数据不支持 |
