# 词律探微 · 实现产物（竖切片）

本目录是**可运行的竖切片**，不是完整产品。目标：证明"引擎 → API → 前端"这条链路在真实数据上成立，并把接口契约与不变量先落地。

## 5. 模型副功能：选型与闸门

**一个实测教训**：两个模型都曾被判「结构化不合规」，真实原因都是 **token 预算被思考吃掉**——
qwen 在长输入下 700 tokens 会返回空正文，flash 低于 2600 时正文被截断。把预算给足后两者都能稳定输出 JSON。
实现里对「空正文」额外重试一次（`finish_reason` 会记进返回），避免把预算问题误判成能力问题。


### 5.1 为什么选 qwen

| 模型 | 结构化输出 | 延迟 | 结论 |
|---|---|---|---|
| `qwen3.8-27b`（关思考，`max_tokens=1200`） | 稳定，JSON 合规 | 3–4 s | **默认** |
| `step-3.7-flash`（`max_tokens=2600`） | **预算给足就可合规** | 9–16 s | 双模型对照的第二意见 |

两个模型都会犯声律事实错误（历史实测：qwen 曾把入声全标真、flash 曾误判平仄占比），
所以它们**不接触事实计算**，只消费事实卡。

### 5.2 四道闸门与已知局限

| 闸门 | 检查什么 | 不过时 |
|---|---|---|
| 结构 | 宽容解析 JSON（严格 → 去代码围栏 → 截取花括号） | 判 `blocked`，不展示草稿 |
| 事实 | 草稿与依据里的每个阿拉伯数字都能在事实卡中找到出处（含 0.05 容差） | 判 `blocked`，列出违规数字 |
| 越界 | 价值判断词表（优于、更胜一筹、艺术价值更高…） | 判 `blocked`，列出命中词 |
| 标注 | `verification` 含「未验证」且 `boundary` 非空 | 判 `blocked` |

**必须知道的局限**：事实闸门只能验证「数字有出处」，**不能验证「数字被放在了正确的字段上」**——
把上片比例说成下片，数字仍在白名单内。因此候选一律标「未验证」，需要人对照事实卡核对。
闸门也存在误杀（模型写「百零二」里的 0 曾被判为卡外数字），处理方式是提示词禁止卡外数字 + 白名单放行 0；
若仍被拦，界面会显示违规详情，可人工判断。

## 6. 前端视觉：字体、配色与空状态

### 6.1 为什么要打包字体

龙蜥（Anolis）上没有楷体/宋体，原字体栈 `KaiTi, SimSun` 会整体落空，中文掉到无中文字形的
serif 上——**本机看着正常，迁移后直接缺字**。现在把思源宋体（OFL）裁成项目实际用到的
3,226 字随产物分发：

| 项 | 值 |
|---|---|
| 字重 | Regular / Medium 两档（`public/fonts/*.subset.woff2`） |
| 体积 | 751 KB + 762 KB（全字库各 12 MB） |
| 字符集 | Tier 1 快照正文与题名 + 前端源码 + 风格索引词人名 + **本地题库（公开 700 + 保密 300 题面/答案）** + 常用标点 |
| 已知缺字 | 1 个：`𨓦`（U+284E6，CJK 扩展 B，源字体本身没有该字形），由系统字体兜底 |
| 重新生成 | `pip install fonttools brotli` → `APP_QUIZ_DIR=/path/to/quiz python app/scripts/build_fonts.py` → `npm run build` |
| 授权 | SIL OFL 1.1，`public/fonts/OFL.txt` 为原文 |

字体子集表已裁掉竖排与排版特性表（`GSUB/GPOS/VORG/vhea/vmtx` 等），实测每字重省约 4 KB；
体积主要来自 3,226 个 CFF 字形轮廓本身，所以**实际 751/762 KB 高于前端计划 §8 的单字重
≤400 KB 目标线**——这是取舍：目标机内网部署、包体不设限，优先保证一个字都不缺。
若以后要压体积，方向是换更简的字形源或按页分片，不是删字符。

`tests/test_fonts.py` 会分别校验语料与题库的每个字都在子集里；语料/题库扩容后忘重跑
脚本会直接失败。字符集最初漏了题库题面（9 个字，如「仅/优/劣/哪/率/配/阈」），
现由构建脚本扫描题库并配 `EXTRA` 兜底，两条防线都在。

### 6.2 配色

三态开关（跟随系统／日间／夜间）放在顶栏，写 `localStorage` 的 `cilv-theme`；
首屏由 `index.html` 的内联脚本先定 `data-theme`，避免夜间用户看到一帧白屏。
所有颜色走 token（`--paper` / `--surface` / `--track` / `--mark` 等），组件里不再出现硬编码色值；
昼夜两套 token 见 `styles.css` 顶部。演示或截图可用 `?theme=dark` 直接指定。

### 6.3 空状态与控件

首屏、问答、评测、检索都给了明确的落点：首页三个真实案例卡直接进解题页；问答页是作品下拉框 +
三个示例问题；检索页挂载即出一次结果并给推荐词；评测页说明三口径与耗时。输入控件统一 `.field`，
暗色下不会漏改。

顶栏除主题开关外还有**全局检索**（`/` 聚焦，回车直接进检索页并带上关键词）与**帮助面板**
（板块速览、三档口径边界、快捷键），避免「这套系统能做什么」只能靠口头讲。
检索页底部接了同调统计（作品数、句数分布、仄比中位数、朝代分布），点结果里的词牌名即加载；
解题页在答案下方留一段「推理链留档」，按 `solve_id` 可再次取回推理链。

**内容区有错误边界**：某一页渲染异常时，React 19 默认会卸载整棵树——用户看到的是整屏空白，
连「这一页坏了」都不知道。`ErrorBoundary` 包在内容区（不是整个应用外层），所以出问题时
顶栏与左侧导航照常可用，内容区显示错误原文与「回到概览／重试本页」，切页自动复位。
`scripts/check_pages.py` 用真实浏览器逐页验证「有内容 + 无未捕获异常」，专门防这一类问题。

## 8. 已知边界

- **逐字四声是本地字典口径**，不是官方标注；官方只提供逐句 `ping_count` / `ze_count`。接口用 `source` 与 `tier_label` 如实标注。
- **C4 引文**默认取后段最长句，因此原始整段与金标常不同；官方判分只要求"可定位"，归一化后一致。
- **检索已按三模式实现**；若索引文件缺失会回退内存子串（响应里 `index=memory` 可辨识），不会静默给出空结果。
- **未引入 Tailwind**，所以"关闭 preflight"这一条在本目录尚未触发；接入 Tailwind 时必须按契约 M6 执行。
- **C5 的整段逐字不追求一致**：引文是语义候选，金标任选；公平口径是代理字段（已全对）。
- **监听默认 `0.0.0.0`**：便于评审从各自电脑访问；只允许本机时设 `APP_HOST=127.0.0.1`。
- **示例题面**由后端从本地题库读取，不进入前端产物；题库不在位时 `/api/demo` 返回 404 并说明路径。
- **导出是同步的**：初版契约规划的是「异步导出任务 + 下载端点」，实现改为 `POST /api/revision/export` 直接返回 CSV、
  `GET /api/revision/exports` 查历史——单机单用户、导出量在千行级，同步更直接，幂等键语义未变。
  导出记录表在运行时懒创建，不改构建期校订库的 schema 口径。
- **图谱只有元数据层**：史证（词人生平、历史事件、作品互文）接口 `total=0`，界面显示"待发布"，不用推测内容补全；单焦点邻居上限 30，超出如实截断。焦点可分享（`/graph?focus=tune:临江仙`），作品节点点击跳到 `/work?id=`。
