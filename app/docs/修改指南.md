# 修改指南 · 从改代码到线上生效

> 这份文档回答一个问题：**我要改点东西，怎么让它出现在公网网址上？**
>
> 一句话：**在本机改 → 提交推送 → 发一个 Release → 服务器自动部署**（约 20–40 分钟）。

---

## 0. 先记住三件事

| 事 | 为什么 |
|---|---|
| **在本机改，不要在服务器上改** | 服务器上跑的是发布包的副本（不含 `.git`），改那边下次部署就被覆盖了 |
| **改完要发 Release，服务器才会更新** | 部署代理只认 GitHub Release，不会自动拉 git 仓库 |
| **大文件走 LFS** | `app/data/*.sqlite3` 超过 100 MB，GitHub 单文件硬限制 |

## 2. 标准流程（4 步）

### 第 1 步 · 在本机改

按要改的东西选位置：

| 改什么 | 改哪里 |
|---|---|
| 声律计算、证据生成 | `app/backend/core/engine.py` |
| 接口、路由、返回结构 | `app/backend/app.py` |
| 三层语料与作品库 | `app/backend/core/corpus.py` |
| 检索 | `app/backend/core/store.py` |
| 智能体兜底 | `app/backend/core/agent.py` |
| 页面 | `app/frontend/src/pages/*.tsx`（18 页） |
| 路由 | `app/frontend/src/App.tsx` |
| 样式与主题 | `app/frontend/src/styles.css`（走 token，不写死色值） |
| 判分措辞、口径、闸门 | `app/backend/rules.json`（**改这个不用改代码**） |
| 文档 | 根目录 `*.md`、`app/docs/`、`app/reports/` |

### 第 2 步 · 本地自检

```bash
cd "C:/Users/25920/WorkBuddy AI/2026-11-03-18-28-47"

python -m unittest discover -s app/tests      # 235 条用例
python app/scripts/check_contract.py          # 契约 49-49-43 三方一致
python app/scripts/check_invariants.py        # 不变量 13 条

cd app/frontend && npm run build && cd ../..   # 含 tsc --noEmit
```

三条都过了再往下走。**测试没过就别推了**——现在 Release 是本机脚本发的，会把半成品推上线。

### 第 3 步 · 提交推送

```bash
git add -A
git commit -m "简述改了什么、为什么"
git push origin main
```

> 凭据已配好（凭据管理器里的 `gho_` token），**不会弹授权框**。
> 推大文件前如果报 `You must have push access to verify locks`，
> 跑一次：`git config lfs.https://github.com/.access https://lzitong01-wq:<token>`

### 第 4 步 · 发 Release（服务器自动部署）

```bash
bash scripts/release.sh
```

它会依次：构建前端 → 打包 → 建 Release → 上传 89 MB 资产 → 校验可下载。
上传完成后，服务器上的部署代理（300 秒轮询一次）会发现新版本并自动部署。

**盯进度**：

```bash
# 服务器上看下载/部署进度
ssh 龙蜥 'ls /tmp/cilv-*.parts/ 2>/dev/null | wc -l; journalctl -u cilv-deploy-agent -n 5 -o cat'

# 部署完确认
ssh 龙蜥 'grep DEPLOYED /opt/cilv/.deploy-state; curl -s http://127.0.0.1:8080/api/health | head -c 200'
```

**验证**（本机，真实浏览器）：

```bash

```

## 3. 几种常见改动的注意点

### 只改文案 / 措辞 → 改 `rules.json`
`app/backend/rules.json` 是判类措辞、公式口径、C5 边界文本、越界词表的外置配置。
改完**不用改代码**，但要重新打包（`release.sh` 会自动做）。

### 改前端页面
- 字体子集要覆盖新出现的字：改了语料或题库后必须重跑 `scripts/build_fonts.py`，
  否则新字显示豆腐块（`tests/test_fonts.py` 会拦住）
- `release.sh` 里已经自动跑 `npm run build`，不用手动构建

### 改了语料 / 题库 → 要重建索引
```bash
python app/scripts/build_tier2_locator.py    # 重建 Tier 2 索引（165 MB，会走 LFS）
python app/scripts/build_fonts.py            # 重建字体子集
```
> ⚠️ 重建 `tier2_locator.sqlite3` 会让仓库多存一份 165 MB（git 保留历史版本）。
> 频繁重建会让仓库快速膨胀，**只在语料真的变了时重建**。

### 只改后端代码（不动数据）
最常见的情况，改完直接走第 2–4 步就行。

## 4. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `refusing to allow an OAuth App to create or update workflow` | token 缺 `workflow` scope | 正常，`.github/workflows/` 推不上去，用 `scripts/release.sh` 发版 |
| Release 资产上传返回 400 | 资产名含中文 | `release.sh` 已改成纯 ASCII，别手改回去 |
| **服务器版本没更新，代理日志也没报错** | **GitHub API 配额耗尽**（未认证 60 次/小时，代理 5 分钟轮询一次，几小时就满） | 查 `ssh 龙蜥 'cat /opt/cilv/.deploy-state'` 的 `FAIL_COUNT`；给 `/etc/cilv/deploy.env` 配 `GITHUB_TOKEN`（配额 5000/小时） |
| 服务器部署失败，日志 `Interactive authentication required` | sudoers 路径不全 | `systemctl` 的 `/bin` 与 `/usr/bin` 两个路径都要写 |
| 服务器部署静默失败（软链不切换） | 解压用了 `--strip-components=1` | 已修，别改回去 |
| 代理下载卡住、刷进度条 | 服务器连不上 `github.com`（只有 `api.github.com` 通） | 代理已改用 API 端点，别改回去 |
| 公网打不开 | 本机装了 Tailscale，域名被 fake-IP 劫持 | **换台没装 Tailscale 的机器打开**，或用 `http://100.97.100.2:8080` |
| `ssh` 弹账号选择框 | 凭据管理器有多条 `github.com` 条目 | 命令里带 username：`https://lzitong01-wq@github.com/...` |

### 服务器上「部署没发生」时先查这两处

```bash
ssh 龙蜥 'cat /opt/cilv/.deploy-state'      # FAIL_COUNT 非 0 = 连续失败已停手
ssh 龙蜥 'journalctl -u cilv-deploy-agent -n 20 -o cat'
```

`FAIL_COUNT` 满 3 会停止自动部署（保护机制）。恢复：

```bash
ssh 龙蜥 'printf "DEPLOYED_TAG=<当前版本>\nFAIL_COUNT=0\n" > /opt/cilv/.deploy-state'
```

## 5. 服务器上的东西在哪

```
/opt/cilv/
  current → releases/<tag>          软链，指向当前版本
  releases/<tag>/                   各版本并存（回滚用）
  releases/manual/                  最初手工部署的旧版（可删）
  bin/deploy-agent.sh               部署代理脚本
  .deploy-state                     记录已部署版本与连续失败次数
/etc/cilv/deploy.env                环境配置（GITHUB_REPO、轮询间隔等）
/etc/systemd/system/cilv.service            应用服务单元
/etc/systemd/system/cilv-deploy-agent.service  部署代理单元
/etc/sudoers.d/cilv-deploy          部署代理的重启权限白名单
```

**常用命令**：

```bash
ssh 龙蜥 'systemctl status cilv'                    # 服务状态
ssh 龙蜥 'journalctl -u cilv -f'                    # 实时日志
ssh 龙蜥 'systemctl restart cilv'                   # 重启
ssh 龙蜥 'journalctl -u cilv-deploy-agent -f'       # 部署日志
ssh 龙蜥 '/opt/cilv/bin/deploy-agent.sh --version'  # 已部署版本
```

**手动回滚**（部署失败时自动回滚，也可以手动）：

```bash
ssh 龙蜥 '
  ls -1t /opt/cilv/releases/ | head -3             # 看有哪些版本
  ln -sfn /opt/cilv/releases/<上一个tag> /opt/cilv/current
  systemctl restart cilv
'
```
