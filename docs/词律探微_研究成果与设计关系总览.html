03 / DOMAIN & REUSE

先保留概念，再判断能复用什么

基础设施调查的成果是“可承担的角色与边界”，不是已经选定的数据源，更不是资源排行榜。

对象

调名、词调、体式不是一回事

同调可异名，同名可能异调；词谱对体式的描述也有来源差异。

词作 → 归入词调
词调 → 名称／多个体式
词谱 → 描述体式
实际作品 ↔ 所选规范
字音

字形不能直接等于唯一声调

字音需要语境和体系。四声、平仄、韵脚位置与韵部分类应分开。

文本位置 + 语境 → 候选读音
具体音系下 → 四声／平仄
韵脚 + 所用韵系 → 韵部
自注也是证据，不自动成为唯一真值
解释

声情不等于简单情感标签

形式、词调／音乐传统、文献理论和具体表达之间存在解释环节。

原始材料 → 形式描述
比较归纳 → 理论桥梁
解释结论 ↔ 限制／反例
形式相近，不自动证明情绪相同
依据：S02 S04

最值得保留的复用结论

学术依据、人工核对入口、机器可用数据和本次派生标注，可以由不同来源承担。代码可复用、数据可获取、学术上适用、允许再利用，是不同问题。

ACCESS IS NOT A BOOLEAN

accessible／available 要怎样进入设计？

不用给每个搜索结果填满一张表；候选越接近实际采用，才逐步深入调查这些维度。

① 在不在、找不找得到

存在／失效／仅书目；普通索引、站内搜索或专业汇总。

② 人怎样拿到

公开、账号、机构入口、人工申请；正文与评论可能不同。

③ 程序怎样拿到

API、批量下载、结构化网页、浏览器交互；当前工具失败不等于站点失效。

④ 拿来用有何代价

许可、更新、人工介入、调用成本和适配成本；不合成一个“总分”。

NEXT DISCUSSION / 本轮建议

接下来，先回答四个决策问题

这是对后续讨论的建议，不是新增项目排期或新的强制流程。

A / 范围与验收

第一版要证明什么价值？

五项官方功能的最低表现、研究／教学／维护的侧重、库内／库外输入等还有未决项。

拿已有 W1—W6 与样本讨论闭环；不能以“容易演示”替代真正需求。
B / 复用路径

什么现成方案能减少总工作量？

比较现有系统／平台整合、成熟框架或 SDK、必要定制；同时看数据体系适用性和取用成本。

衡量接入、补代码、维护、部署的总成本，而不是只数组件多少。
C / 判别性验证

哪些不确定性会改变选择？

候选字音能否覆盖目标文本？体式能否合理保留歧义？证据能否定位并支持所述判断？

只做能区分候选路线的小测试；不再泛搜，也不假装只有工程细节尚未完成。
D / 推荐与确认

哪些可以推荐，哪些仍须暂留？

分别列依据、假设、代价和未验证处，再决定采用／不采用／继续验证。

“不预设必须采用”保持为开放选项，不能自动变成“第一版决定不用”。
