# 未知一律拦截，不默认取值

系统对"无法判定"的处理原则是 fail-closed：读不到的字音、无法唯一对齐的体式、缺失的官方字段，都必须进入 unknown 状态并显式呈现，不允许用默认值或猜测值填补。与之相对的做法（未知按支持处理、按首值取用、猜平仄）在本项目被明确禁止。

## 为什么

两处反面证据：参考项目 chinese-poetry-analyzer 在前端读不到字音时用 `charCodeAt(0) % 2` 猜平仄；cc-switch 的能力表在未声明时按"支持"处理。两者都会把不确定性藏进结果——前者污染声律事实，后者让模型承担它并不具备的能力。在本项目里，声律数值一旦被污染，1000 题的字段通过率将失去意义，而这类错误极难被发现（因为它看起来是个正常数字）。

另外，本项目实测多音字可行性上界为 99.16%、27 句在数学上无解——这 27 句只能被标为无法判定，不存在"算出来"的可能。

## 备选与否决原因

- **未知按"平"或"仄"默认**：否决——轻声与未识别字会造成系统性偏移。
- **多值时静默取首**：否决——题库的金标引文正说明取值需可复现且可解释。
- **把"未知"从产品中隐藏，只在内部标记**：否决——研究者必须知道哪些结论有缺口。

## 后果

- 每条结论都可能带 unknown 比例，界面需支持"带缺口"的展示形态。
- 引擎的判定轨迹需要三态（已证成／已证否／未知），且"未知"要有预先定义的影响策略，而不是一律忽略。
- 无法判定项进入校订建议队列，成为人工复核的输入而非噪声。
