# 运行时零外网依赖，数据落到只读单文件

产品运行时不做任何外网访问、不做运行时第三方安装、不引入运行时在线模型服务以外的网络调用；全部数据处理在构建期完成并落到只读的单文件数据库，启动时校验 schema 版本。所有外部调用（含内网模型端点）都必须有显式超时、重试上限与降级路径，且引擎结果不得被模型阻塞。

## 为什么

部署目标是龙蜥 Anolis OS 的内网离线环境。参考项目给出的三个反面证据：cc-switch 依赖 models.dev、npm registry 等联网元数据；magpie 每日上报随机 ID 与使用统计；fangcun 的 CLI 全部走线上 checker，且其核心服务仓库 `lyy0323/check_rhyme` 经 GitHub API 与网页双重核实均为 404 —— 想自托管也无源码可取。任何一个运行时外网依赖，都可能在答辩现场变成不可用。

## 备选与否决原因

- **运行时 pip install 补依赖**：否决——内网无外网，且不可复现。
- **运行时调用外部字音/词谱服务**：否决——同上，且数据授权不清晰。
- **保留运行时在线模型**：否决——离线演示会直接失效；模型只能是可选增强。

## 后果

- 数据处理（拼音归一化、词频、繁简映射、索引）全部下沉到构建脚本，运行只读产物。
- 第三方数据的分发必须先确认授权；`chinese_word_rhyme` 的 19.6MB 词谱源自 sou-yun.cn 且未见授权说明，明确不进入交付物。
- 降级必须是产品能力而非事故处理：模型不可用时，解析与解题照常可用。
